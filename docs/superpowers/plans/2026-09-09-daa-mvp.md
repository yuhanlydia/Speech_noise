# Declarative Acoustic Attention MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a training-free DAA pipeline that lets Qwen2.5-Omni declare acoustic blocks, select query-relevant blocks, enforce the declaration through pre-softmax audio-KV masking, and decompose selection versus reasoning failures.

**Architecture:** Preserve the existing QACR implementation as a baseline. Add pure block/protocol primitives, a DAA controller/hook for Qwen eager attention, a Qwen wrapper extension, a pair-level pipeline, and a standalone evaluator with declared/fixed block controls.

**Tech Stack:** Python 3.10+, PyTorch, Pydantic, PyYAML, soundfile, Transformers Qwen2.5-Omni, bitsandbytes for NF4, pytest.

**Spec:** `docs/superpowers/specs/2026-09-09-declarative-acoustic-attention-design.md`

## Global Constraints

- Same-waveform use/ignore pair invariant remains mandatory.
- Global block declaration is generated once per waveform and reused across both queries.
- No silent fallback from model-declared to fixed blocks.
- Focus is enforced before attention softmax, not by post-softmax V scaling.
- Only post-audio query/generated positions consume the restricted audio context.
- `layers=[]` means all Thinker attention layers.
- DAA is training-free in MVP; QACR remains unchanged as a baseline.
- GPU success is not claimed until run on the target CUDA environment.

## Current verification boundary

The new DAA core was developed test-first in a CPU environment. Full CUDA/Qwen execution is deliberately left as a target-machine validation step; no empirical DAA accuracy claim is made by this implementation plan.
